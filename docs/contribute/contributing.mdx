Bug reports, ideas and pull requests are all welcome. Here is how to make yours easy to accept.

## Issues

Open one on [GitHub](https://github.com/emplio-app/emplio/issues/new/choose) and pick a template:

| Template | It asks for |
|---|---|
| **Something's wrong** | What happened, what you expected, how to make it happen again, and where: self-hosted (which version or commit) or Emplio Cloud. |
| **An idea** | What you'd like Emplio to do, and why it matters to your business. |

Report security problems privately instead. See [Security](/contribute/security).

## Pull requests

<Steps>
  <Step title="Open an issue first for anything big">
    For anything bigger than a small fix, agree on the approach in an issue before you spend time on it.
  </Step>
  <Step title="Make your change">
    See [Build from source](/developers/build-from-source). Keep each pull request to a single change, match the style of the code around it, and add or update a test when you change behaviour.
  </Step>
  <Step title="Check it">
    ```bash
    bun run typecheck
    ```
    The tests need Postgres and Gitea. CI runs them on every pull request, so you can leave them to it.
  </Step>
  <Step title="Open the pull request">
    The template asks for **What this changes and why** and **How you checked it**.
  </Step>
  <Step title="Sign the CLA once">
    On your first pull request, a bot asks you to sign the [contributor agreement](/contribute/cla). It takes a minute, and you keep the copyright in your work.
  </Step>
</Steps>
