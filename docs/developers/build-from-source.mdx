To run your own changes, build Emplio's images from the code instead of downloading them. You need [Bun](https://bun.sh) 1.3 and [Docker](https://docs.docker.com/get-docker/).

<Steps>
  <Step title="Clone and install">
    ```bash
    git clone https://github.com/emplio-app/emplio && cd emplio
    bun install
    ```
  </Step>
  <Step title="Build and start">
    ```bash
    ./setup.sh --build
    ```
    The first time, it asks the same three questions as the installer and writes `.env`. A build takes about 8 minutes on a small server. Run it again after each change.
  </Step>
  <Step title="Check the types">
    ```bash
    bun run typecheck
    ```
    Run this before you push.
  </Step>
</Steps>

## Dev servers

```bash
bun run dev
```

This runs the web app (`next dev`) and the API (`bun --watch`) together, reloading as you edit. The API needs Postgres, Gitea and the runner to reach. It reads the same settings the app container gets: `DATABASE_URL`, `GITEA_URL`, `GITEA_TOKEN`, `COMPUTER_RUNNER_URL`, `RUNNER_TOKEN`, `ENCRYPTION_KEY` and `OPENROUTER_API_KEY`. Run `bun run db:migrate` once against a fresh database.

The runner joins the `emplio-app` container to each person's network, so computers and browsers work end to end only with the app in Docker. Use `./setup.sh --build` to check those.

## Tests

| What | Command | Needs |
|---|---|---|
| Backend | `cd backend && bun run db:migrate && bun run test` | Postgres and Gitea |
| Runner | `bun test runner` | Nothing; Docker is faked |
| Whole install | `bash docker/smoke.sh` | Docker, and a clean copy with no `.env` |

[`.github/workflows/ci.yml`](https://github.com/emplio-app/emplio/blob/main/.github/workflows/ci.yml) shows exactly how CI starts Postgres and Gitea for the backend tests. CI runs all three on every pull request, so you can leave the tests to it.

<Tip>`docker/smoke.sh` builds everything, signs up, runs a real computer and browser, and removes all of it afterwards.</Tip>
